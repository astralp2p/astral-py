# Wire vector corpus

`wire_vectors.json` pins the byte-level behaviour of the SDK's encoders and
decoders. It is **pure data**. It is written before any implementation code and
it must never import the SDK — a test that reads this file and a test that reads
the SDK's own output are the two independent halves of the check, and they stop
being independent the moment the corpus is generated by the thing it validates.

Nothing in this file is guessed. Every vector carries a `source` naming one of
three authorities, and a `ref` locating it inside that authority.

## Authorities

| Authority | Location | Pinned at |
|---|---|---|
| `astral-docs` | `../astral-docs/master` | `1d6787c` |
| `astral-go` | `../astral-go/main` | `5c18d9c` |
| live node | alias `furry-bolt`, identity `03b2704948bb…` | pins astral-go `5c18d9c` |

Where astral-docs disagrees with astral-go or the live node, **the live node and
astral-go win**. Every such disagreement is recorded in the affected vector's
`notes` and is a candidate astral-docs bug report.

## File shape

```
{
  "corpus", "schema_version", "generated", "purpose",
  "authorities", "precedence", "source_kinds", "fields", "counts",
  "vectors":          [ … ],   // positive: these bytes are correct
  "negative_vectors": [ … ],   // these bytes must be REJECTED
  "gaps":             [ … ]    // what could not be sourced, and why
}
```

## Vector schema

| Field | Meaning |
|---|---|
| `id` | stable identifier. Never reuse an id for a different value. |
| `astral_type` | the Object Type name. The empty string means an untyped object. |
| `description` | human-readable statement of the value. |
| `value` | the value in a JSON-expressible form. Documentation, **not** an encoding — never assert against it. |
| `binary` | the **payload** bytes, lowercase hex. No type tag, no length prefix. |
| `json` | the JSON encoding, where one is defined. |
| `text` | the text encoding, where one is defined. |
| `canonical` | `Stamp ‖ string8(ObjectType) ‖ payload`. |
| `channel_frame` | `string8(ObjectType) ‖ bytes32(payload)` — one binary-channel frame. |
| `polymorphic_field` | `string8(ObjectType) ‖ payload` — the self-delimiting generic object field. |
| `object_id_preimage` | the exact byte sequence that gets hashed. |
| `object_id` | the resulting ObjectID, `data1…` zBase32. |
| `source` | `doc-literal` \| `go-derived` \| `live`. Describes the **`binary`** field. |
| `ref` | provenance for `binary`. |
| `json_source`, `json_ref`, `text_source`, `text_ref` | present only when that encoding's provenance differs from `source`/`ref`. |
| `corroborated_by` | on `doc-literal` vectors: the independent implementation that reproduces the same bytes. |
| `notes` | traps, disagreements, implementation warnings. |

### The two object framings, side by side

Both are present on most vectors, because getting them backwards is the single
most common reimplementation bug:

```
channel_frame      string8(type) ‖ bytes32(payload)     type OUTSIDE the length
polymorphic_field  string8(type) ‖ payload              no length at all
canonical          Stamp ‖ string8(type) ‖ payload      no length at all
bundle element     bytes32( string8(type) ‖ payload )   type INSIDE the length
```

The bundle form is pinned by the `bundle.uint8_string8` vector.

## Source kinds

- **`doc-literal`** — the hex appears verbatim in astral-docs. `ref` names the
  file and section, e.g. `astral-docs@1d6787c topics/binary-encoding.md § Slices`.
  These vectors additionally carry `doc_hex_matches_astral_go: true` and a
  `corroborated_by` field: the generator asserts astral-go reproduces the
  documented bytes exactly, and the build fails if it ever stops doing so.
  There are only ten of these in the whole corpus — astral-docs contains just
  nine hex code blocks in total plus one in `primitive-types/object.md`.

- **`go-derived`** — produced by **executing** astral-go's encoder at
  `5c18d9c`, not by reading it. `ref` names the file and function, e.g.
  `astral-go@5c18d9c astral/map_value.go mapValue.WriteTo`.

- **`live`** — captured off the wire from the running node. `ref` names the
  probe: endpoint, query and capture date. These are the most valuable vectors
  because they close the loop on the whole stack at once.

## Negative vectors

`negative_vectors` entries carry `expect: "reject"` instead of an expected
encoding. They pin the *decoder's* strictness — the presence-flag rules in
particular, where astral-docs and astral-go genuinely disagree (see
`neg.container_presence.0x00`).

## Gaps

`gaps` records what a wire-fidelity corpus wants and could not get, with the
reason. A gap is not a TODO for the implementer to guess around: it marks
territory where the SDK must not assume anything until the gap is closed.

## Adding a vector

1. **Pick a source first.** If you cannot get the bytes from astral-docs, from
   running astral-go, or off the live node, you do not have a vector — you have
   a guess. Add it to `gaps` instead.

2. **Doc-literal**: transcribe the hex, then add it to the `DOC` map in the
   generator so the build asserts astral-go agrees. A mismatch is a finding, not
   a merge conflict — record it and stop.

3. **Go-derived**: add a call to `obj(...)` (for a registered Object: emits
   payload, JSON, text, canonical, channel frame, polymorphic field, ObjectID)
   or `plain(...)` (for a composite reached through a probe struct) in the
   generator, rerun it, and rebuild.

4. **Live**: capture with a read-only probe. Record the endpoint, the query, the
   probe script and the date in `ref`. Never edit the node.

5. **Cross-check.** The build validates every vector for internal consistency:
   `canonical`, `channel_frame` and `polymorphic_field` are recomputed from
   `astral_type` + `binary`, and `object_id` is recomputed as
   `zbase32(len(preimage) ‖ sha256(preimage))` with leading `y` stripped. A
   vector that fails any of those is malformed.

6. **Give it an id that survives.** Tests reference ids; renaming one silently
   drops a test.

## Provenance of the live vectors in this build

The live node's apphost **request** path was stalled when this corpus was built:
it accepted connections and pushed the `host_info_msg` greeting on all three
endpoints but never answered any inbound message. Two live vectors
(`live.apphost.host_info_msg`, `live.json_envelope.host_info_msg`) were captured
fresh over `ws://127.0.0.1:8624/.ws` during this build. The remaining seven were
captured earlier in the same investigation, over `tcp:127.0.0.1:8625` against the
same node process at the same commit, and are recorded verbatim in the survey
notes cited in each `ref`. Both sets were re-derived byte-for-byte by astral-go
during this build, and the JSON and text forms were checked to decode back to the
same payload — so the live and go-derived halves of the corpus agree everywhere
they overlap. See the `gaps` entry `gap.live.everything_past_the_greeting`.
